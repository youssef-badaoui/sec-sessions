Jour 2 / Lab 2

Injection SQL via le formulaire de connexion

Ce lab construit la requête de login en concaténant directement le nom d’utilisateur et le mot de passe dans le SQL. L’application affiche aussi la requête finale quand le login échoue, ce qui rend le chemin d’injection très facile à observer.

Rappel rapide sur l’injection SQL

Une injection SQL apparaît quand l’entrée de l’utilisateur est insérée dans une requête comme du code au lieu d’être traitée comme une donnée. Si la base de données interprète l’entrée de l’attaquant comme une partie de la requête, l’attaquant peut changer la logique.

Dans ce lab l’impact est un contournement d’authentification. L’objectif est de transformer la clause WHERE en quelque chose qui s’évalue toujours à vrai.

D’où vient la vulnérabilité

La route de login construit la requête SQL avec une f-string. Aucun placeholder, donc la base de données reçoit l’entrée brute de l’utilisateur dans la requête.

if request.method == 'POST':
    username = request.form['username']
    password = request.form['password']

    query = f"SELECT * FROM users WHERE username='{username}' AND password='{password}'"
    user = conn.execute(query).fetchone()

Comme l’application affiche la requête exécutée en cas d’échec de login, on peut voir exactement comment le payload modifie le SQL.

Exploitation et correctif

On utilise un nom d’utilisateur valide comme admin et on injecte dans le champ mot de passe avec ' OR 1=1 --.

Entrée

username=admin
password=' OR 1=1 --

Requête construite

SELECT * FROM users WHERE username='admin' AND password='' OR 1=1 --'

Le OR 1=1 injecté rend la condition vraie, et le guillemet final est neutralisé par le commentaire SQL. L’application connecte alors avec la première ligne renvoyée par la base.

Correctif

Le correctif s’articule autour de deux points : valider l’entrée avant de construire la requête, et utiliser des requêtes préparées pour que la base traite les valeurs comme des données.

1. Validation de l’entrée

La validation ne remplace pas les requêtes préparées, mais elle permet de rejeter les valeurs clairement invalides avant qu’elles n’atteignent la base.

import re

def is_valid_username(value):
    return re.fullmatch(r'[A-Za-z0-9_]+', value) is not None

if not is_valid_username(username):
    return render_template('login.html', error='Invalid username format')

Pour un formulaire de login, c’est utile pour des champs comme le nom d’utilisateur qui suivent un format connu.

2. Utiliser des requêtes préparées

C’est le vrai correctif. La requête garde des placeholders, et les valeurs sont passées séparément.

query = "SELECT * FROM users WHERE username=? AND password=?"
user = conn.execute(query, (username, password)).fetchone()

Avec cette version, un payload comme ' OR 1=1 -- est traité comme une chaîne de caractères, pas comme du code SQL.
