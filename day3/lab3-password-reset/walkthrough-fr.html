Jour 3 / Lab 3

Reset de mot de passe avec un lien token-utilisateur cassé

Ce lab ressemble à un flux de reset normal, mais l’étape finale fait confiance au nom d’utilisateur reçu dans le formulaire au lieu de récupérer le compte cible directement à partir du token.

Rappel rapide

Un token de reset ne doit fonctionner que pour le compte pour lequel il a été émis. Si le serveur ne valide que le token et pas la relation token-utilisateur, un attaquant peut demander un token pour un compte et l’utiliser pour réinitialiser un autre.

D’où vient la vulnérabilité

Le token est stocké avec un nom d’utilisateur, mais la requête de reset ne vérifie que si le token existe et est encore actif.

if request.method == 'POST':
    token = request.form['token']
    username = request.form['username']
    new_password = request.form['new_password']

    reset = conn.execute(
        "SELECT * FROM reset_tokens WHERE token=? AND expired=0",
        (token,)
    ).fetchone()

    if reset:
        conn.execute(
            "UPDATE users SET password=? WHERE username=?",
            (new_password, username)
        )
<input type="text" name="username" value="{{ username }}">

Comment fonctionne l’exploit

On demande un reset pour son propre compte, on récupère un token valide depuis sa boîte mail, puis on change le champ username avant de soumettre le nouveau mot de passe.

Demande d’un token de reset

POST /forgot-password
username=user

Utilisation du token contre un autre compte

POST /reset-password
token=<token-valide-du-user>
username=admin
new_password=hacked123

Le token est valide, donc l’application l’accepte. La mise à jour s’applique alors à admin parce que le serveur fait confiance au champ du formulaire.

Correctif

Lier la recherche du token au nom d’utilisateur, ou mieux : ne dériver le nom d’utilisateur que depuis le token.

# requête plus sûre
reset = conn.execute(
    "SELECT * FROM reset_tokens WHERE token=? AND username=? AND expired=0",
    (token, username)
).fetchone()
# encore mieux : ignorer complètement le username envoyé
if reset:
    conn.execute(
        "UPDATE users SET password=? WHERE username=?",
        (new_password, reset['username'])
    )
